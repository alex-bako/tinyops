# M3.T3 — Live availability check and suggestion

Slice: M3.T3 of [M3](../roadmap/milestones/M3.md). Depends on M3.T2 (shared handle rule,
committed as `7d7f340`). Requirements: OBI-5, OBI-6, OBI-7, OBI-9; assumptions A2, A3, A4, A5.

## Objective

A person typing a workspace name learns *before* pressing Continue whether the derived
handle is free, and is offered a free alternative when it is not. The answer shown is
always the answer for the handle currently in the field, never a late reply for an
earlier one.

## Exclusions

- The submit-time collision path — a handle taken between the answer and Continue. That is
  M3.T4; until it lands, such a collision still surfaces as today's generic banner.
- The create-workspace form (`/home/workspaces/new`). That is M3.T5; this slice only has to
  leave the hook reusable by it.
- Reserved-word blocklists, rate limiting beyond requiring authentication (D3's accepted
  tradeoff), and any change to the handle format or the `workspaces_handle_normalized`
  constraint — all milestone non-goals.

## Boundary

    StepWorkspace  ──props──  OnboardingFlow
                                   │ useWorkspaceHandleAvailability(handle)   [client, debounced]
                                   ▼
                       checkWorkspaceHandleAvailability(handle)               ["use server"]
                                   ▼
                       rpc workspace_handle_available(text) -> boolean        [security definer]

The hook lives at the flow level because `canContinue` is computed there; `StepWorkspace`
receives the result as a prop and only renders it.

## Design decisions

### The RPC returns a boolean and nothing else (OBI-7)

`public.workspace_handle_available(target_handle text) returns boolean`, `security definer`,
`set search_path = public`, raising `42501` when `auth.uid()` is null. Granted to
`authenticated`, revoked from `anon, public` — the pattern at
`supabase/migrations/20260509003000_workspace_lifecycle_rpc.sql:329-349`.

Availability is `not exists (select 1 from public.workspaces where handle = target_handle)`
with no archived/visible filter, because the thing being predicted is the `handle text not
null unique` column (`supabase/migrations/20260509001000_workspaces.sql:4`). Any row at all
makes the handle unavailable, archived or not. Filtering would make the answer disagree with
the constraint that ultimately decides.

### The suggestion is built in the action, not the RPC

Acceptance requires the offered suggestion to be itself verified free, and requires `-3` when
`-2` is also taken. Keeping the RPC boolean-only means the loop lives in the server action:
probe `<handle>-2`, `-3`, … and return the first free one. Capped at `-10`; past that the
field reports taken with no suggestion rather than hammering the database.

The loop runs only on the taken path, so the common case stays one round trip.

### The hook keys the answer to the field, not to the request

The milestone names this as the most likely defect. A ref holds the handle the hook most
recently *asked* about; every resolved promise compares the handle it was asked for against
that ref and drops itself if they differ. This kills both orderings — a slow `park` landing
after a fast `park-t`, and a `park` reply arriving after the person has cleared the field.

    // illustrative - verify against the file as written
    const latest = React.useRef("")
    // ...
    latest.current = handle
    const answer = await check(handle)
    if (latest.current !== handle) return   // a reply for a handle nobody is looking at

Debounce: **300 ms**, a module constant (`HANDLE_CHECK_DEBOUNCE_MS`), confirmed against the
local stack during the exit gate. The milestone records it as a constant, not a decision.

### No call for a handle the format already rejects

The hook returns `idle` and fires nothing unless `isValidWorkspaceHandle(handle)` — T2 already
answers `pa` and `park-` without a round trip, and the RPC would only echo "free" for a value
that can never be stored.

### An unreachable database does not block the flow (OBI-9)

`unknown` is treated as "not known taken". `canContinue` requires *known free or unknown*;
only `taken` blocks. A stopped Supabase stack costs a sentence in the hint, not the flow.

## State

    type WorkspaceHandleAvailability =
      | { status: "idle" }       // nothing to ask about, or the format already failed
      | { status: "checking" }
      | { status: "free" }
      | { status: "taken"; suggestion: string | null }
      | { status: "unknown" }    // the check itself failed - do not block on it

## Failure / security

- The RPC is `security definer`, so it must not trust its caller: it raises `42501` when
  `auth.uid()` is null, and `search_path` is pinned.
- What it leaks is exactly one bit about one handle a person just typed, which is the
  accepted D3 tradeoff (OBI-7). It never returns a workspace name, id, member count or
  timestamp, and the contract test asserts `anon` cannot execute it at all.
- The action returns a discriminated result rather than throwing; any store error becomes
  `unknown` and is logged, never rendered.
- The suggestion loop is bounded (9 extra probes) so a pathological handle cannot turn one
  keystroke into unbounded database work.

## Migration / rollback

Additive: one new function, no table or constraint change, no backfill. Rolling back is
`drop function public.workspace_handle_available(text)`; the client treats a missing function
as an error, which lands in `unknown`, which does not block onboarding.

## Risks / unresolved

- **Regenerating `database.types.ts` may produce diff noise** unrelated to this slice if the
  local stack has drifted from the migrations. Mitigation: `supabase db reset` before
  generating, and review the diff for anything outside the new function.
- **Debounce interval is a guess until the exit gate.** 300 ms; confirm by hand on the local
  stack (milestone step 2-4), adjust the constant if it feels laggy or chatty.
- `@testing-library/user-event` is still not installed (A5); every typing test drives repeated
  `change` events through the existing `type()` helper, and the debounce is driven with
  `vi.useFakeTimers()`.
